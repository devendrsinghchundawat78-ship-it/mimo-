# Draft AI takeaways backend

Not deployed. This SQL migration must be reviewed against live production migration versions before applying. No importer exists yet and `ai_use_allowed` defaults to false. This is intentional: the existing Android form allows user-edited title and private descriptions, so its `saves` fields are not safe inputs for auto AI. The app needs a vetted server-side importer that records public metadata provenance and source-specific rights before enabling this route, plus auto-save and Reanalyze UI wiring. Never copy `saves.content`, manually entered form fields, media, TMDB, Movie of the Night, or unreviewed YouTube API Data into `ai_metadata`.

POST `{saveId:uuid, reanalyze:boolean}` with a Supabase access token. The server verifies identity, a live owned save, vetted metadata, an atomic quota, then sends title/description to Groq gpt-oss-20b using a server-side key and strict JSON output. Reanalyze skips cache but still consumes quota. Responses and errors are no-store. Store `MIMO_GROQ_API_KEY` only in Supabase secrets after reviewing migration and provider policy. Globally enabled ZDR must remain on. Current cap: 6/user/hour, 20/global/UTC minute, and 600/global/UTC day, below Groq's observed Free limits of 30 RPM and 1,000 RPD. Foreign keys cascade on hard deletion. Soft deletion and source-revision invalidation still need a trusted cleanup path before production.

Security review notes: service-role RPC EXECUTE grants still need an independent anon/authenticated check after deployment. The provider Free limits also include tokens/minute and tokens/day; enforce both before exposing to production. The importer must perform a rights allowlist per source, not trust client-provided provenance or direct access to the private table. Do not use this route to process E2EE content: decryption for server-side AI needs a separate informed consent design, or choose on-device inference.

In-app AI identity: show "Mimo AI" for the assistant name. This endpoint only generates structured takeaways and does not accept conversation questions, so it cannot answer "which AI are you?" today. Any later conversational route should identify itself as Mimo AI, avoid naming the inference provider in its persona text, and keep provider/data-processing disclosures in the app privacy notice rather than misstate them. Do not imply this source-only draft is a deployed chat feature.
